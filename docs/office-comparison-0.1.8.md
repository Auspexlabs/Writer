# Writer 0.1.8 与 Microsoft Office：继续核查

> 后续更新：本文保留当时的对比与复现记录；当前实现已继续补齐普通页眉表格单元格编辑、通配符／格式查找、多区域剪贴板、手动分页、组合内部编辑及讲义／备注打印。最新交付状态见 [实施状态](office-implementation-status.md)。

核查时间：2026-09-28（北京时间）。基线是本地 0.1.8 源码及已打包的原生引擎，Git 基础提交为 `f44087cdfa8fbcd6399eba286b1b43a562f4b10f`，工作区有未提交改动。本报告不代表 `/Applications` 安装版或线上版本已更新。

**审计时复现 9 项缺陷：Word 1 项、Excel 5 项、PowerPoint 3 项。后续修复已全部接入源码，并通过下述复现样本回归。** 本文缺陷表保留修复前现象；前轮列出的专业功能与复杂文档兼容缺口仍然存在。不能把“按钮已增加”“函数已注册”“原始对象被保留”当作完整支持。

最新修复证据：[保存重开与绘制结果](audits/office-0.1.8-fixes.json)、[浏览器 DOM 与像素验证](audits/office-0.1.8-browser.json)、[本轮新增功能与安装包验收](audits/office-0.1.8-expansion.json)。同时补上跨表整列引用解析、动态数组完整打印区域，SUMIFS 和 AVERAGEIFS 使用实际存储数据汇总。本轮完整回归为 941 项原生测试、1126 项界面与桥接测试通过，无跳过。**本地 0.1.8 DMG 已重打，包含这些修复及后续新增功能，并完成签名、公证和盖章；未上传发布。**

微软侧以 Microsoft 365 桌面产品文档为参照；区分 Mac、Windows 和订阅功能。本轮没有运行 Microsoft Office 应用进行逐屏对照。公式预期来自官方语义，Writer 结果来自实际实现及临时文件保存重开；绘制问题使用真实绘制函数的命令记录定位。

## 1. 修复前复现的缺陷（保留审计记录）

P1：影响内容正确性、计算或关键工作流，应先修。P2：影响格式、外观或操作完整性。

| 编号 | 功能与触发方式 | 当前结果 | 应有结果／影响 | 优先级与证据 |
|---|---|---|---|---|
| W1 | 页眉内有表格，修改表格旁的文字后，经界面序列化保存 | 原表格保留，但表格文字另存成正文段落；样本标记出现次数从 1 变成 2，并多出空段落 | 不应重复内容；公司抬头、表格页眉可能越改越乱。页脚走同一处理路径，但本次原生文件复现使用页眉 | P1；`WordEditor.dc.html:554`、`DocxSection.cs:497`；DOCX 保存重开 |
| E1 | A1=1、A2=`=""`、A3=2，计算 `COUNTA(A1:A3)` | 返回 2，原生保存后缓存也是 2 | 应为 3；公式返回空字符串的单元格也应计数。影响统计结果和其他软件读取缓存 | P1；`sheet-engine.js:964`；求值及 XLSX 保存重开 |
| E2 | `IFERROR(MAP({1,0,2},LAMBDA(x,1/x)),99)` | 整体变成单值 99，右侧没有溢出结果；保存后也是如此 | 按 MAP 与 IFERROR 的逐项数组语义，预期为 `1、99、0.5`；单项错误不应吞掉其他有效项 | P1；`sheet-engine.js:984`；求值及 XLSX 保存重开 |
| E3 | 同上 A 列数据，`SUMIFS(A1:A1048576,A1:A1048576,">0")` | 返回 `#REF!` | 应为 3；SUM 等已改为遍历实际数据，但 SUMIFS 仍触发百万格物化限制。不是旧的 80×20 网格问题 | P1；`sheet-engine.js:20,376`；实际公式求值 |
| E4 | A1=20、B1=10，条件格式为“单元格大于 `$B$1`” | A1 不着色 | 应使用 B1 的值进行比较。当前将引用字符串直接转数值，得到 NaN；界面及打印共用此路径 | P2；`sheet-conditional.js:17`；实际规则求值 |
| E5 | A1=`SEQUENCE(3)`，A1:A3 设置红黄绿三色色阶 | 值是 1、2、3，但三格全黄 | 统计应包含公式溢出区域；同样三个值逐格存储时，控制样本正确显示红黄绿。本复现是溢出子格尚未物化为存储单元格的状态 | P2；`sheet-conditional.js:8`；动态数组与字面值对照 |
| P1 | 列表使用罗马数字，从 III 开始；导出 PNG | 导出变成 `1.、2.` | 应保留 `III.、IV.`；忽略了列表的实际编号标记和起始值 | P2；`slide-canvas.js:22`；真实文本解析结果 |
| P2 | 表格单元格含 64px 红色富文本，导出 PNG | 使用表格默认的 24px 白色文字 | 文本框富文本已增强，但表格分支仍取纯文字及默认字体，导出外观不一致 | P2；`office-io.js:454`；真实 Canvas 绘制命令 |
| P3 | 将组合对象整体旋转 90°，导出 PNG | 子对象按原角度绘制，组合的 90° 旋转没有进入绘制命令 | 导出应保留父组合旋转；组合分支过早递归子对象，跳过父变换 | P2；`office-io.js:442`；真实 Canvas 绘制命令 |

Excel 语义参照：[COUNTA 包含公式空字符串](https://support.microsoft.com/en-us/excel/functions/counta-function)、[MAP 逐项映射](https://support.microsoft.com/en-us/excel/functions/map-function)、[IFERROR 数组逐项返回](https://support.microsoft.com/en-us/excel/functions/iferror-function)。E2 的具体组合结果是依据这些文档推导的预期，未声称在 Excel 应用中实跑。

条件格式参照：[数值、公式与引用条件](https://support.microsoft.com/en-US/Excel/use-conditional-formatting-to-highlight-information-in-excel)、[色阶按区域数值分布呈现](https://support.microsoft.com/en-us/excel/use-data-bars-color-scales-and-icon-sets-to-highlight-data)。E4/E5 的 Writer 故障均有实际求值输出，并非仅凭按钮缺失推断。

**排除的一项疑似问题：** `WRAPROWS({1,2},5,0)` 返回一行 `1、2`，没有补成五列，符合微软对 `wrap_count` 大于等于元素数时的说明，未列入缺陷。[官方语义](https://support.microsoft.com/en-us/excel/functions/wraprows-function)

以下功能矩阵保留审计时状态；其中 W1、E1–E5、P1–P3 已完成上述修复，不再作为未修问题。

## 5. 实际替代程度与后续顺序

- 普通短文、小表和简单演示已有相当多可用工具；仍应按具体文件验证保存和导出，不能承诺全面无损。
- 正式合同／论文的复杂排版、财务模板和数据分析、复杂动画和媒体演示，当前缺口会直接影响交付。
- 先处理 W1、E1–E3 的内容和计算正确性，再修 E4/E5 与 P1–P3 的画面一致性；之后补常用操作和专业功能。
- PDF 离线依赖已随 0.1.8 本地包分发，前轮已做断网验证；它不等于新增 OCR 或完整 Acrobat 功能，本轮没有将其重复列为待下载项。

不提供“达到 Office 百分之多少”的估算：功能数量不能代表语义兼容、复杂文件保真或大文件速度。VBA／插件、旧格式／XLSB、完整加密权限、实时协作与云端版本仍另有工作量，平台和账号依赖见[既有边界说明](office-comparison-0.1.7.md#11-对标对象的平台与云服务边界)。
