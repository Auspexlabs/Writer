## 0. 我们现在站在哪里

**引擎已经过了"能不能"这一关。** docx/xlsx/pptx/md 读写、pdf 只读、刚合并的 FreeMind 思维导图读写，路径寻址、`add/set/remove/move`、按注册表生成的 `help`、CLI + MCP + HTTP 三种入口，保存只写原生树，没碰的部分逐字节不变（14 个 docx、12 个 pptx、10 个 xlsx 样本往返，87 个 md 样本字节级一致，`tests/Writer.Tests`）。文本、段落样式、列表、表格、图片、超链接、单元格值/公式/数字格式、幻灯片/形状/图片/表格这一层，引擎和界面都能落盘，agent 和人改的是同一个文件。

**界面的问题不是"做得少"，而是"做了却没写进文件"。** 三个编辑器的功能区看上去接近 Office 网页版，但相当一部分按钮只改浏览器里的画布，`ui/engine.js` 在保存时根本不会把它们翻译成引擎命令，重新打开就没了：

- Word：页面设置、页眉页脚、页码、分页符（这四项引擎侧刚合并，`engine.js` 还没发送）、水印、行距/段前段后/首行缩进、上下标、表格样式/边框/底纹、图片环绕、批注、修订、目录（写成普通段落）
- Excel：斜体/下划线/字号、对齐、自动换行、边框、合并单元格、列宽行高、冻结窗格、筛选、条件格式、图表、工作表顺序
- PowerPoint：切换、动画、备注、隐藏页、主题、幻灯片大小、旋转、轮廓、透明度、层级、段落对齐

**有几处比"没保存"更糟，会悄悄改坏文件，需要最先处理：**

1. 修订模式下插入的文字以"带下划线的正文"写入，删除的文字直接消失（`engine.js runsOf`：`INS` 当下划线、`DEL` 跳过）
2. Word 表格"合并右侧单元格"只改 `colspan`，引擎没有 `gridSpan/vMerge`，保存后那一行少一个单元格
3. Excel 网格固定 80 行 × 20 列（`sheet-engine.js NC/NR`），更大的表看不到也改不了；插入行列时越界的单元格被丢弃并在保存时删除（`SheetEditor insDel`）
4. 编辑含公式（OMML）、域、行内图片的 Word 段落时，这些对象会被替换掉（`DocxRuns.ReplaceContent` 只保留批注/脚注/书签标记）

**显示保真同样是差距**：Word 没有真实分页，Excel 看不到文件里已有的合并/图表/条件格式，PowerPoint 不渲染母版、版式和主题，设计过的稿子打开后"变素"。

## 5. 路线图：接下来要补的差距

按"先不丢数据，再补中国办公用户每天都用的，最后补长尾"排序。前 4 项是 P0。

1. **Word 修订与批注落盘（P0）**：现在开修订会把插入写成下划线正文、把删除直接抹掉，批注重开即丢；引擎要建模 `w:ins/w:del` 和 `comments.xml`，界面读写走引擎，至少先做到"不改坏"。
2. **Excel 网格上限 80×20（P0）**：改成按需渲染/虚拟滚动，插入行列不再丢越界单元格；不然稍大一点的表就不能交给这个应用。
3. **Word 页眉页脚、页码、页面设置、分页符（P0，进行中）**：引擎侧已合并（`document.page/orientation/margin/columns/header/footer`、`pagebreak`），剩下的是 `engine.js` 把 `doc.page`、`doc.header/footer` 和 `<hr data-pb>` 翻译成 `set /` 与 `add --type pagebreak`，并在打开时读回来显示。
4. **Word 目录写成 TOC 域（P0）**：生成 `TOC \o "1-3"` 域并标记脏，Word 打开即可更新；页码要等真实分页（第 8 项），先保证结构正确。
5. **Excel 常用结构落盘（P0/P1）**：合并单元格、列宽行高、冻结窗格、筛选、条件格式、边框/对齐/字号/斜体，都是现成的 OOXML 元素，界面已经有交互，只差引擎属性和 `saveXlsx` 的映射；同时读回文件里已有的合并和列宽。
6. **PowerPoint 母版/版式/主题渲染（P0）**：打开设计过的稿子不能"变素"，否则用户不敢在里面改；先渲染母版背景、版式图形和主题字体颜色，编辑母版可以不做。
7. **Word 表格合并单元格与表格样式（P1）**：`gridSpan/vMerge`、表格样式 id、边框、底纹、列宽；现在"合并"会让行少一格，是数据问题不只是样式问题。
8. **打印/导出 PDF 保真（P1）**：真实分页、页码、每页页眉页脚，走设计里定的 HTML → 无头 Chromium 路线，同时解决 Excel 打印区域和 PPT 母版渲染的打印版。
9. **图表落盘与显示（P1）**：Excel 三种图表写成 `c:chart` 部件，三个格式都要能显示文件里已有的图表（先只读渲染）。
10. **PowerPoint 动画/切换/备注/隐藏页落盘（P1）**：这些都已在界面上做了交互，写进 `p:timing`、`p:transition`、`notesSlide`、`show="0"`；备注同时要读回来。
11. **Word 段落间距、首行缩进、行距、上下标、中文字体（P1）**：公文排版的最低要求；引擎加段落 `spacing/indent` 属性，字体列表加宋体/黑体/仿宋/楷体。
12. **脚注/尾注（P1）**：读出显示、可新增，Word 网页版都有。
13. **图片环绕与浮动（P1）**：引擎生成 `wp:anchor`，界面的靠左/居中/环绕才有意义；顺手修掉百分比宽度按像素写入的问题。
14. **编辑含公式/域/行内图的段落不丢对象（P1）**：`DocxRuns.ReplaceContent` 把 `m:oMath`、域和带图的 run 当作标记保留；公式编辑器本身放 P2。
15. **Excel 函数覆盖与缓存值（P1/P2）**：补 SUMIFS/COUNTIFS/XLOOKUP/日期文本函数，保存时写入浏览器算出的缓存值，让 `view text` 和其他程序看到结果。
16. **拼写检查（P2）**：编辑区打开浏览器拼写检查是一行改动；语法检查交给 AI 面板。
17. **数据验证（P1）与数据透视表（显示 P2，创建 P3）**：验证是表单类文件的常用功能；透视表先做到显示不丢。
18. **演讲者视图（P2）**：备注落盘后，用第二个窗口放当前页、下一页、备注、计时。
19. **版本历史（P2）**：在工作区旁边按保存点留快照，比协作先做，也是 AI 改动可追溯的基础。
20. **协作与分享（P3）**：产品是本地优先，多人实时协作明确不追；共享文件靠"外部改动自动重载"。

## 附：判断依据与不确定的地方

依据：功能区定义在各编辑器 `renderVals()` 里的 `tabsDef` 与 `B('…')/M('…')`；什么能写进文件以 `ui/engine.js` 的 `saveDocx/saveXlsx/savePptx` 与 `src/Writer.Core/Registry.cs` 为准；文件读写能力以 `src/Writer.Formats/{Docx,Xlsx,Pptx,Pdf,Markdown}` 为准；微软侧以 learn.microsoft.com 的 Word/Excel/PowerPoint for the web 服务说明为主，演讲者视图、页脚页码、分栏三处按更新的支持文章修正为"网页版有"。

不确定、需要跑一下确认的：

- CSV/TXT/HTML 导入：文件选择器接受这些扩展名，但 `engine.js upload` 只按扩展名建类型，未知扩展名按 Markdown 打开；`office-io.js` 里的 `importFile`（CSV 解析、HTML → docx）没有任何调用者，疑似旧代码。
- 修订模式下 `ensureIns` 插入的零宽空格（`​`）是否会写进文件；从代码看只有"全部接受"时才清理。
- Word 图片百分比宽度按像素写入，是从 `blocksFromHtml` 的 `parseFloat` 推断的，没有实际跑过。
- 写作期间 `e102e42`（docx 页面设置/页眉页脚/分页符）和 `218050c`（思维导图适配器）合并进了 main，相关行已按合并后的引擎状态改写；其余"进行中"项（视图模式、连续缩放、PDF 单页/连续视图、浮动导航、思维导图编辑器）还没有落地，按给定清单标注。
- 微软服务说明页面部分内容较旧（Excel 页写"替换不可用"、PowerPoint 页写"无演讲者视图/页脚不可插"），本文按后来的支持文章标为"有"；如果基线要严格对齐某个日期，这几行需要复核。
